<h2>
    Git Strategy
</h2>
<h3>
    Branches
</h3>
<p>
    A standard branch name example should look like this: <code>feature/dashboard</code>. Here is a list of recommended branch names to write and use during development:
</p>
<h4>
    Base Branches
</h4>
<p>
    The following names are recommended during development:
</p>
<ul>
    <li>
        <p>
            feature
        </p>
    </li>
    <li>
        <p>
            bugfix
        </p>
    </li>
    <li>
        <p>
            hotfix
        </p>
    </li>
    <li>
        <p>
            test
        </p>
    </li>
</ul>
<h4>
    Sub Branches
</h4>
<p>
    There is no standard naming convention for this part. However, one of the reasonable advice we can give you is to specify the major or minor requirement you are given to satisfy. For example, if you are designated to implement a dashboard feature, the branch name you should use would be <code>feature/dashboard</code>. 
</p>
<p>
    If a future name might cause confusion, then you are free to specify at a reasonable manner, as a suffix. For example: <code>feature/dashboard-user</code>. 
</p>
</br>



<h2>
    Getting Started
</h2>
<p>
    Contributions are welcome, including bug fixes, features, documentation, tests, and other improvements.
</p>
<h3>
    Setup
</h3>
<p>
    For all contributions, please follow the recommended instructions:
</p>
<ol>
    <li>
        <p>
            Fork this repository
        </p>
    </li>
    <li>
        <p>
            Select a filesystem path to clone your forked repository, beforehand
        </p>
    </li>
    <li>
        <p>
            Clone your forked repository at the selected filesystem path
        </p>
        <pre><code class="language-bash">git clone [repository-url]
cd [repository-directory]</code></pre>
    </li>
    <li>
        <p>
            Create a new branch to push your implementations
        </p>
        <pre><code class="language-bash">git checkout -b [main-branch-name]/[sub-branch-name]</code></pre>
    </li>    
</ol>
</br>
